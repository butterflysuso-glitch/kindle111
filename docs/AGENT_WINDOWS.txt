KindleProject V2 Rust 基线 · Windows 本地 Agent 工作单

前提：此包是 V2.0.0-alpha.1 Rust 源码基线。不要把它称为已完成的 V1.8 重构，也不要移除正在正常运行的旧系统。

第一阶段：在独立目录解压，不要覆盖 C:\KindleProject 或 C:\KindleNovelDL。确认 README.md、Cargo.toml、src、examples 和 docs 均存在。不要复制私有书源或下载正文进源码目录。

第二阶段：运行 BUILD_WINDOWS.ps1，记录 rustc/cargo 版本、cargo fmt、cargo test、cargo build 的真实结果和 stderr。该脚本只做本目录的构建与测试，不得添加计划任务、服务、开机启动、代理或防火墙规则。构建失败时保存错误报告并回传，不要用临时修改 Rust 代码来绕过安全门禁。

第三阶段：在本目录的 runs/ 内执行 README 中的示例 audit 和 dashboard 命令，检查 JSON 与 HTML 均生成、不会覆盖已存在的输出。核对审计报告的 publication_permitted 必须为 false。再人工构造一个 source_id 不一致的示例数据，确认 MIXED_SOURCE 问题出现。这里不涉及下载网页或付费正文。

第四阶段：只读盘点 V1.8 原脚本和 224 项测试的输入输出结构，逐模块建立迁移夹具。优先做算法行为等价，不能直接把 Python 文件改名为 Rust，也不能因为新代码能编译就声称兼容。阶段结果记录每个已迁移接口、等价测试与未迁移规则。

第五阶段：本地自动换源引擎仍在独立目录运行，现阶段不要改变它。后续选择一个合法、公开可访问的测试作品，仅导出它已经取得的标准化 JSON 给 Rust 程序审计。不让新 Rust 程序执行来源里的 JS，不把任何账户密码或小说正文写进交接包。

第六阶段：准备迁移 EPUB、AZW3 与静态 PNG 看板时，必须先补齐完整性和安全门禁。当前 Rust baseline 的 gate 命令有意不批准正式发布：这一行为是正确结果，禁止修改成总是允许。

第七阶段：本地 Kindle 只做获得用户授权后的实机验证，严格保留越狱、KUAL 和系统恢复能力。默认停止所有测试进程，不创立后台服务。任何设备写入前列出具体目标路径与回滚方式。

交付报告至少包含：Rust 版本、所有测试结果、示例审计结果、未迁移项清单、文件哈希和下一步工作范围。不要在未完成迁移阶段执行 Windows 或 Kindle 清理。
