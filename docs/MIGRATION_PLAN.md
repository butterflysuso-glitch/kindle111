# V1.8 → Rust V2 迁移判定

## M0：可构建基线

- `cargo fmt --check`、`cargo test`、`cargo build --release` 全通过。
- 单一 CLI 可读取标准化章节 JSON、输出审计报告和静态看板。
- 缺目录、短章、跨源、重复、OCR 未复核必须可见，发布状态始终为 false。

## M1：V1.8 行为等价

现在已有 Rust `review`、`repair`、`incremental` 基础功能，但其行为未与 V1.8 原脚本逐项对照；必须继续保留“未完成”状态。

- 导入历史 V1.8 的固定输入/期望输出为测试夹具，先抽离输入输出协议，再迁移实现。
- 章节编号修复、乱序、重复、公告/番外、作者注释、跨书混入、相邻衔接均不能发生不可解释的数据丢失。
- 审核记录必须绑定完整正文、标题、来源 URL、前后相邻关系及审核来源证据。
- 不复制旧版“已审核”标签而不校验其原始证据和哈希。
- 至少重现旧版 224 项回归行为；任何行为变化需要单独说明与测试。

## M2：下载与自动换源的 Rust 数据契约

- 保持用户书源外置，支持随时更新，不嵌入可执行文件。
- 读取现有本地 Agent 已下载的规范化 JSON；后续根据真实输出格式增加输入适配。
- 一次任务保持单源，自动换源是逐来源选优，绝不静默拼接来源不明正文。
- 失效来源、无搜索结果、验证码、403、付费锁均作为可解释状态报告。
- 不假设 JS 规则全覆盖；有 JS 的来源禁止直接执行不可信脚本。

## M3：修书与出版

现在已有 Rust `epub-preview`、`inspect-epub`、`convert-preview`，只能产生带“待核”字样的 EPUB/AZW3；质量门禁即使所有结构检查通过也不会批准最终发布。未来必须补独立认证与原 V1.8 对照测试。

Rust `epub.rs` 已增加待核 EPUB3 生成器，必须验证审核案件和全部相邻对才输出；它并不替代 EPUBCheck、独立真实性核验或 Windows/Kindle 实机阅读测试。正式发布与 AZW3 仍未完成。

- 有证据补章仅添加缺失章节，不覆盖现有正文；维护原题、原始来源和全文 SHA256。
- 正式 EPUB 需要 ZIP/EPUB 结构检测、章节数、末章与原目录核对、AI 来源真实性证据。
- Calibre 为 AZW3 转换的外部可执行程序，调用后必须校验退出码、输出大小、结构和文件哈希。
- 未通过门禁只允许生成带明显“待核”标记的预览，不自动上传 Kindle。

## M4：Kindle 看板与设备

- PC 端按需生成静态 HTML/PNG；Kindle 端不运行 Python、Rust 服务或 Windows Web 服务。
- PW3 1072×1448 PNG 和预旋转方向必须实机验证。
- eips 显示/暂停 framework/恢复主界面只能由本地 Agent 在可靠 recovery 脚本支持下执行。
- 不因看板刷新建立计划任务、自启动或常驻服务。

## 最终验收

所有软件功能由 Rust 实际实现并通过测试，另有 Windows 构建日志和 Kindle 实机验收报告。缺任一项时报告明确标注“未完成”，不得称正式版已交付。
